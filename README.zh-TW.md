# DDR 踩點／重心分析（DDR Step Analyzer）

[日本語](README.md) ｜ **中文**

用人體骨架（RTMPose Halpe26，含腳跟／腳趾）分析 DDR 遊玩影片：實際踩的位置、重心、省力指標，並給出規則式修正建議（門檻以高階玩家設定）。

完全在本機執行：不需要 AI 訂閱、不呼叫任何雲端 API，影片不會離開這台電腦。只有第一次安裝時需要網路（套件與模型下載）。

![分析畫面](docs/images/screen.png)

## 下載與安裝（Windows）

1. 打開 [Releases 頁面](https://github.com/xkamome/ddr-step-analyzer/releases/latest)，下載 `ddr-step-analyzer_v1.3.zip` 這類名稱的 zip（數字是版本）。
   （也可以按本頁綠色的「Code」→「Download ZIP」，內容相同）
2. zip 按右鍵 →「解壓縮全部」，建議放在 `C:\ddr-step-analyzer`（避開桌面與 OneDrive 資料夾）。
3. 雙擊資料夾裡的 `setup.bat`。出現藍色「Windows 已保護您的電腦」時，按「其他資訊」→「仍要執行」。
4. 等 10–20 分鐘（會自動安裝 Python 3.12 與約 360 MB 的骨架模型，不需管理員權限）。
5. 完成後桌面會出現「DDR ステップ解析」捷徑，之後雙擊它就能用；關掉瀏覽器分頁即結束。

需求：Windows 10/11 64-bit、記憶體 8 GB 以上、空間 3 GB、安裝時要有網路。
日文使用者請看 zip 裡的 `はじめにお読みください.txt`。

## 啟動

```
start.bat          # 或 python server.py（--no-browser 不開瀏覽器、--no-auto-exit 不自動結束）
```

瀏覽器會打開 http://127.0.0.1:8765（預設日文介面，右上角可切中文）。按「＋ 新增影片」可以貼本機路徑或上傳檔案。
CPU 上「準確」模式約 0.3 秒／幀，2 分鐘的影片約 20 分鐘。

**自動結束**：網頁每 4 秒回報一次；所有分頁關閉（或 90 秒沒回報）且沒有影片在分析時，伺服器 10 秒後自動結束。
重新整理頁面不會誤關；分析中關掉瀏覽器，會等分析完成再結束。

## 移植到別台電腦（給別人用）

1. 雙擊 `make_package.bat` → 產生 `dist/ddr-step-analyzer_v<版本>.zip`（約 100 KB，只有程式與說明；版本在 `ddrpose/__init__.py`）。
   發佈新版：改 `__version__` → 打包 → `gh release create vX.Y dist/ddr-step-analyzer_vX.Y.zip`，使用者從 Releases 頁面下載。
2. 把 zip 傳給對方。對方照 zip 裡的 `はじめにお読みください.txt`（日文）操作：
   - 解壓到 `C:\ddr-step-analyzer`（避開 OneDrive 同步資料夾）→ 雙擊 `setup.bat`。
   - `setup.bat` 會自動：找 Python 3.11–3.13，沒有就用 winget 或官方安裝檔裝 Python 3.12（使用者權限，不需管理員）→
     在 `%LOCALAPPDATA%\ddr-pose\venv` 建虛擬環境（放在專案外，避開 Windows 路徑長度限制與 OneDrive 同步）→ 裝 `requirements.txt` → 下載模型（約 360 MB）→ 在桌面建「DDR ステップ解析」捷徑。
   - 之後雙擊桌面捷徑就能用；關瀏覽器即結束。
3. 對方需求：Windows 10/11 64-bit、記憶體 8 GB 以上、空間 3 GB、安裝時要有網路。
4. ffmpeg 用 `imageio-ffmpeg` 套件內建的版本，對方不用另外安裝。
5. 分析結果存在對方電腦的 `data/`；不會帶走你這邊的資料。

命令列也可以直接跑：

```
python -m ddrpose.pose "D:\...\IMG_1194.MOV" data\IMG_1194     # 轉預覽檔＋姿勢擷取
python -m ddrpose.analyze data\IMG_1194                          # 分析（改門檻後重跑這個即可）
```

## 分析流程

1. **姿勢**：YOLOX 偵測人框（每 10 幀）＋ RTMPose-x 逐幀辨識 26 點，追蹤主要玩家。
2. **左右腳校正**：Viterbi 讓左右腳標籤在時間上連續，再用踏板幾何（或側拍時腳的遠近大小）檢查整體是否左右顛倒。
3. **鏡頭移動補償**：原則上鏡頭固定。每 2.5 秒取一個關鍵幀，用背景特徵點（排除玩家）對參考幀估單應矩陣；估計位移超過畫面寬 3%、且下一個關鍵幀也確認，才換一段新的鏡頭位置（逐幀補償會把遊戲畫面、毛巾、人的動作誤當成晃動，讓九宮格抖動）。
   **非遊玩段不分析**：抓不到人、鏡頭對不上參考幀、或雙腳離平常位置超過 1.5 條腿長的幀（例如拿起手機拍結算畫面）不列入分析；3 秒內的缺口視為遮擋，短於 5 秒的片段不算遊玩。
4. **落地偵測**：腳的速度低於門檻（以小腿長正規化）即視為落地；接觸點取前腳掌（腳跟→腳尖 60%）。
5. **踏板校正**
   - 自動（首選）：箭頭板被踩時會亮紅／藍色箭頭燈。把整支影片的亮燈累積到參考幀，四團亮區就是四個箭頭板中心。
   - 自動（備援）：腳印分群。高手常用腳跟踩 ↓、腳尖踩 ↑，落點會偏向中央，只能當參考。
   - 手動：按「校正踏板」拖九宮格四個角對齊踏板外框（滾輪放大、拖空白處平移、雙擊復原、「旋轉 90°」修正方向）。
6. **踏板亮燈判定**：逐幀量四塊箭頭板的亮燈，當作「機台實際判定」：
   - 每一步的板位以亮燈為準；骨架沒偵測到落地、但有亮燈的步會補上（歸給離那塊板最近的腳）。
   - 用亮燈當標準答案校正腳的有效長度（腳跟往後、腳尖往前延伸），自動校正時也微調九宮格。
   - 骨架負責判斷是用腳跟、腳尖還是整隻腳踩。
7. **腳跟離地**：腳跟→腳尖在畫面上的傾角減去「踩平」基準（每隻腳、每塊板各自計算，避免透視誤差），換算成高度；
   腳跟離地時只算前腳掌施力，並把腳跟投影拉回正下方地面。每步附信心等級（高／中／低），低信心不列入統計。
   分析分三階段：亮燈板位 → 分板腳跟基準 → 擬合腳長與九宮格。
8. **重心大幅移動**（`ddrpose/events.py`）：以慣用姿勢（整段中位數，含扶桿後靠）為基準，挑偏離最明顯的 10–20 段，
   附踩點序列與原因推測（交叉步、跳、同一腳連踩、大跨距、手離開扶桿、比平常密集），並統計哪種三步配置之後重心最容易跑掉。
9. **重心**：Winter 分段質量模型。下肢逐段計算，上半身（0.678）放在骨盆→肩膀 63% 處；肩膀不在畫面時退回骨盆。重心在地面的投影，取沿垂直方向（由背景直線估計）與兩腳連線的交點。
10. **指標與建議**：重心左右晃動／偏移、骨盆彈跳、抬腳高度、膝角（側拍才可靠）、落點貼邊／散佈／踩到角落、扶桿比例。門檻寫在 `ddrpose/analyze.py` 的 `TH`。

## 介面

![介面說明](docs/images/overview.png)

①影片選單 ②分析狀態（校正方式、重心算法、步數）③語言 ④新增影片 ⑤影片疊圖 ⑥播放控制與圖層開關 ⑦校正踏板 ⑧時間軸（重心、骨盆高度、落地、踏板亮燈）⑨俯視踏板 ⑩結果分頁。每個部分的詳細說明（日文）見 [README.md](README.md)。

- 右上角可切換中文／日文（介面文字與修正建議都是中日雙語）。
- 「重心事件」分頁：點一下跳到該處以 0.25× 慢放，俯視圖畫出該段重心軌跡與編號腳步。
- 俯視圖方向：依校正結果判斷鏡頭在踏板哪一側，自動旋轉讓鏡頭那側在下方（正面拍＝轉 180°；斜後方 ±60° 內維持 0°），「螢幕」字樣標出遊戲螢幕那邊。
  右上 **↻** 每按一次轉 90°，每部影片各自記在瀏覽器（localStorage）；轉回自動判斷的角度就恢復自動。只改畫法，資料仍是踏板座標。

## 限制

- 單一鏡頭 2D 推估，cm 數值以一格約 28 cm、小腿約 38 cm 換算，是估計值。
- 上半身不在畫面時，重心只能用骨盆推估，看不到上半身前傾或後仰的影響。
- 腳被另一隻腳或扶桿遮住時，該幀的點可能不準（已用內插與平滑降低影響）。
- 單一鏡頭只能量到重心在「畫面水平方向」的位置，介面會標出是哪個方向（例如斜向 ↖↘）。
- 貼地側拍看不到踏板，不適合分析（舊資料移到 `data/_archive/`，不會出現在清單）。
- 最佳拍法：從玩家斜後上方、手機約腰部高度，拍到整個踏板與全身，鏡頭固定不動。

## 資料

`data/<影片>/`：`preview.mp4`（瀏覽器播放用）、`pose.npz`（骨架）、`motion.npz`（晃動補償）、`glow.npz`（亮燈）、`calib.json`（手動校正）、`analysis.json`（分析結果）。
